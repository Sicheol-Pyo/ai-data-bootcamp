# 머신러닝 학습 노트 정리

전체 5개 노트북 + 분류 평가지표 심화 내용을 파트별로 정리했습니다. 퀴즈 전에 훑어보고 넘어가면 좋습니다.

---

## Part 1. 선형 회귀와 로지스틱 회귀 — 예측의 첫걸음

### 지도학습 vs 비지도학습
- **지도학습**: 정답(레이블, y)이 있는 데이터로 학습. 예측값과 정답을 비교해 채점 가능.
- **비지도학습**: 정답이 없는 데이터에서 숨은 구조(그룹, 패턴)를 발견. 채점 기준이 없어 해석이 필요.

### 회귀 vs 분류
- **회귀**: 연속적인 숫자를 예측 (집값, 온도 등). 평가지표: **MSE**(평균제곱오차), **R²**(결정계수).
  - R²는 음수가 나올 수 있음 — "평균만 예측하는 것보다도 못하다"는 뜻이지 버그가 아님.
- **분류**: 범주(카테고리)를 예측 (생존/사망, 스팸/정상). 평가지표: 정확도, 정밀도, 재현율, F1 등.

### 선형회귀
ŷ = w₁x₁ + w₂x₂ + ... + wₚxₚ + b
- **w (가중치/계수)**: 각 피처가 예측값에 주는 영향의 크기와 방향
- **b (절편)**: 모든 x가 0일 때의 기준값 (편향-분산의 "bias"와 헷갈리지 않도록 "절편"이라고 부름)

### 로지스틱 회귀
- 시그모이드: σ(z) = 1/(1+e⁻ᶻ), z는 피처들의 선형결합
- **σ(0) = 0.5** → z=0이 클래스 0/1을 가르는 **결정경계**. z가 선형결합이라 결정경계는 항상 **직선(평면)**
- **오즈(odds)** = p/(1-p) (성공확률 ÷ 실패확률)
- **오즈비(odds ratio) = eʷ**: 피처가 1 증가할 때 **오즈**가 몇 배가 되는지를 뜻함. **확률이 그만큼 배가 되는 게 아님** (확률은 1을 못 넘으므로 단순 곱셈이 안 됨)

### 데이터 분리
- `train_test_split`: 학습/테스트 데이터 분리
- `random_state`: 난수 시드 고정 → **재현성**을 위한 것이지 **편향을 막아주는 장치가 아님**
- `stratify=y`: 원본 데이터의 **클래스 비율**을 train/test에 그대로 유지 (불균형 데이터에서 특히 중요)

### 과적합/과소적합 기초
| 구분 | 특징 | 원인 |
|---|---|---|
| 과적합(overfitting) | train↑ test↓, 격차 큼 | 모델이 너무 복잡, 피처 과다, 노이즈까지 암기 |
| 과소적합(underfitting) | train·test 모두 낮음 | 모델이 너무 단순, 피처 부족 |

### 베이스라인 비교
- `DummyClassifier(strategy="most_frequent"/"stratified"/"uniform")`, `DummyRegressor(strategy="mean")`
- 내 모델이 이 "아무 생각 없는 기준선"보다 나은지 항상 비교해야 함
- R²=0은 DummyRegressor(mean)과 동일한 성능이라는 뜻

## Part 2. 과적합과 교차검증 — 이 점수, 믿어도 될까?

### 홀드아웃(단일 분리)의 불안정성
- random_state만 바꿔도 test 점수가 크게 요동칠 수 있음 (예: 0.958~0.993)
- 단일 숫자보다 **평균 ± 표준편차**로 보고해야 하며, 좋은 시드만 골라 보고하는 건 나쁜 관행

### 편향-분산 트레이드오프
- **편향(bias)**: 모델이 너무 단순해서 데이터의 진짜 패턴을 못 잡아내는 **체계적 오차**
- **분산(variance)**: 학습 데이터를 조금만 바꿔도 예측이 크게 달라지는 **민감도** (과적합과 직결)
- 전체 오차 ≈ 편향² + 분산 + 노이즈 (모델 복잡도에 따라 U자형 곡선)

### 정규화(Regularization)
- **Ridge(L2)**: 계수 제곱합에 페널티 → 계수를 0에 가깝게 축소
- **Lasso(L1)**: 계수 절댓값 합에 페널티 → 계수를 아예 0으로 만들 수 있음 (자동 피처 선택 효과)
- 로지스틱 회귀의 `C`: 정규화 강도의 역수 (C가 작을수록 정규화 강함)

### 학습곡선(Learning Curve)
- 학습 데이터 크기에 따른 train 점수 vs validation 점수 변화를 관찰
- **validation 곡선이 계속 오르는 중** → 데이터를 더 모으는 게 의미 있음
- **validation 곡선이 평평해짐** → 데이터보다 피처/모델 개선이 필요 (데이터 추가는 비용 대비 효과 낮음)

### 교차검증(Cross-Validation)
- **K-Fold / StratifiedKFold**: 분류 문제에서는 클래스 비율 유지를 위해 StratifiedKFold가 기본
- k가 클수록 fold가 작아져 점수 추정의 **분산이 커짐**
- `cross_val_score`(단일 지표) vs `cross_validate`(다중 지표 동시) vs `learning_curve`(데이터 크기별 곡선) — 목적이 다른 함수

## Part 3. 의사결정나무와 앙상블 — 여러 모델을 모으면 강해진다

### 결정트리
- **지니 불순도** G = 1 - Σpⱼ² : 50:50일 때 최대(0.5), 순수 노드일 때 0
- **정보 이득** = 분기 전후 불순도 감소량
- 결정경계가 **계단(축에 평행한 직사각형)** 모양인 이유: 한 번에 **피처 하나만** 기준으로 자르기 때문 (로지스틱 회귀는 여러 피처를 합친 하나의 직선 경계)
- 가지치기: `max_depth`, `min_samples_leaf`, `max_leaf_nodes`

### 앙상블 — Bagging vs Boosting
| | 방식 | 줄이는 것 |
|---|---|---|
| **Bagging** | 부트스트랩 샘플링 + 독립적 병렬 학습 + 평균/투표 | **분산** |
| **Boosting** | 이전 모델의 오차를 다음 모델이 순차적으로 보정 | **편향** |

### 랜덤포레스트
- 두 가지 무작위성: **① 행(데이터) 부트스트랩** + **② 열(피처) 랜덤 서브셋(max_features)**
- 둘 다 있어야 트리들이 충분히 다양해져 평균 시 분산이 실제로 줄어듦
- **OOB(Out-of-Bag)**: 부트스트랩 시 한 트리당 약 37%의 데이터가 사용 안 됨 → 이걸로 별도 검증셋 없이 공짜 검증 가능 (`oob_score=True`)

### AdaBoost
- **샘플 가중치**: 틀린 샘플의 가중치를 높여 다음 라운드에서 더 신경 쓰게 함 (데이터에 붙는 가중치)
- **발언권(Amount of Say)**: 각 stump 자신의 에러율 기반으로 결정되는, 최종 투표에서의 영향력 (모델에 붙는 가중치)

### 그래디언트 부스팅
1. 첫 예측값 = 타깃의 **평균** (상수 예측 중 MSE를 최소화하는 값, DummyRegressor(mean)과 같은 원리)
2. 잔차(실제값 − 현재 예측값) 계산
3. 다음 트리는 **잔차를 예측**하도록 학습 (평균이 아니라 오차 자체를 맞힘)
4. 예측값 += learning_rate × 새 트리의 잔차 예측, 반복

### XGBoost가 GBM보다 나은 점
- L1/L2/gamma **정규화** 내장 → 과적합에 더 강함
- **2차 미분(Hessian)** 정보 활용 → 더 정교한 학습
- **결측치 자동 처리** (sklearn RandomForest는 수동 imputation 필요)
- 일반적으로 더 빠름

### learning_rate
- 너무 높으면 노이즈에 과하게 반응 → 과적합
- 너무 낮으면 n_estimators를 늘려야 하거나 과소적합

### 특성 중요도
- **MDI(`feature_importances_`)**: 학습 중 불순도 감소량 누적, 공짜로 계산되지만 **고카디널리티 피처를 과대평가**하는 편향 있음
- **Permutation Importance**: 학습 후 피처를 섞어 성능 하락polnomial 측정, 더 신뢰할 만하지만 계산 비용 큼
- **한계 3가지**: ① 방향성 없음(항상 양수, 오즈비처럼 +/- 방향을 모름) ② 개별 예측 하나하나의 이유는 설명 못함 ③ 상관관계일 뿐 인과관계가 아님

### 성능 vs 해석력
- 단일 트리: 해석 쉬움(if-else로 설명 가능), 성능은 낮을 수 있음
- 앙상블(RF, XGBoost): 성능 높음, 블랙박스 → 법적 설명 책임이 필요한 경우(대출 거절 등) 단일 트리를 선택해야 할 수도 있음

### 스케일링
- 트리 기반 모델: 분기가 **순서/임계값 비교**만 사용 → 스케일링 불필요
- 로지스틱회귀/KNN/SVM: 피처의 **실제 크기(magnitude)**를 직접 사용 → 스케일링 필수

## Part 4. 피처·파이프라인·데이터 누수 — 새지 않는 실험 설계

### 파생 변수의 3가지 조건
1. 명확한 **비즈니스 가설**이 있어야 함
2. **예측 시점에 사용 가능**해야 함 (누수 방지)
3. 같은 조건의 CV 비교로 **실제 효과가 검증**되어야 함

### 인코딩
- **One-Hot**: 순서/거리 개념이 없는 명목형 변수 (성별, 탑승항구 등)
- **Ordinal**: 실제로 순서가 있는 변수만 (등급, 학년 등)
- `OneHotEncoder(handle_unknown="ignore")`: CV의 특정 fold 학습 데이터에 없던 카테고리가 검증 데이터에 나타나도 에러 없이 처리 (0으로 채움) — CV에서 특히 중요

### 스케일링 종류
- StandardScaler(평균0/표준편차1), MinMaxScaler(0~1), RobustScaler(중앙값/IQR 기반, 이상치에 강함)

### Pipeline & ColumnTransformer
- Pipeline은 **자신에게 주어진 데이터에만 fit** → cross_val_score/cross_validate 안에서 쓰면 각 fold의 학습 조각에만 전처리가 fit되어 **전처리 누수를 구조적으로 방지**
- ColumnTransformer: 컬럼 그룹별로 다른 전처리 적용 후 결합
- GridSearchCV: `이름__파라미터` 네이밍으로 파이프라인 내부 하이퍼파라미터까지 탐색 (`clf__C` 등)
- `best_score_`는 **모델 선택용 점수**이지 최종 일반화 성능이 아님 (별도 테스트셋/중첩 CV 필요)

### 데이터 누수 4가지 유형
| 유형 | 설명 | 막는 법 |
|---|---|---|
| ① 전처리 누수 | train+test 합쳐서 전처리 fit | Pipeline으로 fit 범위를 fold 안으로 제한 |
| ② 타깃/시점 누수 | 타깃 정보나 미래 정보가 피처에 유입 | cross-fitting 인코더(TargetEncoder 등) |
| ③ 검증 누수 | 테스트 점수를 보고 하이퍼파라미터를 고름 (여러 번 시도 후 최고점 선택) | **절차적 규율**: CV 점수로만 선택, 테스트는 마지막에 한 번만. Pipeline으론 못 막음! |
| ④ 시간/중복 누수 | 시계열 순서 무시, 중복 샘플이 train/test에 걸침 | TimeSeriesSplit, GroupKFold |

### 개선 레버 우선순위
**데이터/피처 > 모델 선택 > 하이퍼파라미터 튜닝** (노트북 실측: 피처 +0.1178, 모델 −0.0034, 튜닝 +0.0225 — 데이터셋마다 다를 수 있는 경향성)

## Part 5. 군집화와 차원축소 — 정답 없이 구조를 찾는다

### 지도 vs 비지도 (재확인)
- 지도학습: 예측값 vs 정답 직접 비교 (정확도, R² 등)
- 비지도학습: 정답표가 없어 **내부지표 + 안정성 + 업무 해석**을 종합해서 판단해야 함

### K-Means
- 방식: 중심 잡기 → 가까운 점 배정 → 중심을 평균으로 이동 → 반복(수렴)
- 거리(유클리드) 기반이라 생기는 두 가지 제약: **① 스케일링 필수** (단위 큰 피처가 거리 지배) **② 구형(둥근) 군집 가정** (길쭉/휜 모양엔 약함)
- `n_clusters`(k, 직접 지정), `n_init`(여러 초기화 중 best 선택)
- inertia: 군집 내 거리제곱합. k가 커지면 항상 감소 → 단독 품질 점수로 쓰면 안 됨

### k 결정 — Elbow & Silhouette
- **Elbow**: inertia 감소 폭이 완만해지는 지점(응집도 기준)
- **Silhouette**: 응집도+분리도를 -1~1로 요약, 1에 가까울수록 좋음
- 둘이 다른 k를 가리키면: 어느 한쪽을 무조건 우선하지 않고, 전처리/안정성 점검 후 **비즈니스 제약**(운영 가능한 그룹 수)까지 함께 고려. 단, 데이터가 전혀 지지하지 않는 k를 억지로 채택하면 안 됨

### DBSCAN
- 밀도 기반: `eps`(반경), `min_samples`(최소 인원)
- 라벨 **-1 = 잡음(Noise)**, 어느 밀집 영역에도 속하지 않는 점
- K-Means 대신 써야 할 상황: **① 비구형 군집(초승달 등)** **② k를 모르고 잡음이 많음**

### PCA(차원축소)
- **설명 분산비** = 각 주성분이 설명하는 분산 / 전체 분산
- 2D 시각화가 예: 55.4%만 보존 → 나머지 44.6%는 그림에서 사라짐. "2D에서 가깝다"가 "원래 고차원에서도 비슷하다"를 보장 안 함
- PCA 앞에는 보통 표준화 필요 (분산 큰 피처가 주성분을 지배하는 것 방지)

### 세그먼트 해석
- 군집 번호(0,1,2) 자체는 의미 없음 → 각 군집의 **피처 평균(프로파일)**을 분석해 비즈니스 라벨/액션으로 번역
- 검증: 안정성(시드 바꿔도 비슷한가), 해석 가능성(한 문장으로 설명되는가), 차별성(그룹별 다른 액션이 가능한가)

### 군집을 피처로 (비지도 → 지도)
- 군집 번호를 그대로 숫자로 넣으면 존재하지 않는 순서 관계를 학습 (One-Hot vs Ordinal과 같은 원리)
- 대신 `KMeans.transform()`으로 **각 중심까지의 거리**를 피처로 사용 (순서 없는 연속값)
- KMeans도 **fit을 하는 변환기**이므로 반드시 Pipeline 안에 넣어야 함 → 전체 데이터에 미리 fit하면 **① 전처리 누수**에 해당

## 보너스: 분류 평가지표 심화

### 혼동행렬(Confusion Matrix)
- 행=실제, 열=예측. TP/TN/FP/FN
- 정확도 = (TP+TN)/전체
- 임계값 ↑(보수적): FP↓ FN↑ / 임계값 ↓(공격적): FP↑ FN↓ — **FP와 FN을 동시에 줄일 수 없음** (항상 트레이드오프)

### 도메인별 비용 비대칭
| 상황 | 더 치명적인 오류 | 이유 |
|---|---|---|
| 의료 진단 | FN | 치료 기회를 놓침, 되돌릴 수 없음 |
| 은행 연체 예측 | FN | 손실 회수 불가 |
| 제조 불량 검출 | FN | 불량품이 고객에게 전달됨 |
| 스팸 필터 | FP | 중요 메일 손실 |
| VIP 마케팅 | 상황에 따라 다름 | FP(불쾌감/탈퇴)와 FN(매출 기회 상실) 둘 다 비용 발생 → 실제 비용 추정 필요 |

### 정밀도 vs 재현율
- **정밀도(Precision)** = TP/(TP+FP): "양성이라 예측한 것 중 진짜 양성 비율"
- **재현율(Recall) = 민감도(Sensitivity)** = TP/(TP+FN): "진짜 양성 중 잡아낸 비율" — 완전히 같은 지표, 분야별 명칭만 다름(의료=Sensitivity, ML=Recall)

### F1-score
- 정밀도와 재현율의 **조화평균** (산술평균 아님)
- 극단적 불균형을 훨씬 가혹하게 반영 (정밀도=1.0, 재현율=0.01 → 산술평균 0.505 vs 조화평균 ≈0.0198)

### ROC-AUC
- X축=FPR, Y축=TPR(재현율)
- AUC = "무작위로 뽑은 양성이 무작위로 뽑은 음성보다 높은 점수를 받을 확률"
- 1.0=완벽, 0.5=무작위. **임계값에 무관** → CV fold 간 가장 안정적인 지표

### classification_report
- 클래스별 precision/recall/f1/support + accuracy + **macro avg**(클래스 크기 무관, 단순평균) + **weighted avg**(샘플 수로 가중평균, 큰 클래스가 지배) — 소수 클래스 성능이 궁금하면 macro avg가 더 유용

### 회귀에 혼동행렬이 없는 이유
y가 연속값(무한한 가능한 값)이라 유한한 셀로 나눌 격자 자체가 없음 → MSE/R²(거리 기반) 사용
